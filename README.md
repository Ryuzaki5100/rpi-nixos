# rpi-nixos

Declarative **NixOS** for the **Raspberry Pi 5** (and any other Pi you add),
powered by the [`nvmd/nixos-raspberrypi`](https://github.com/nvmd/nixos-raspberrypi)
installer.

Two images are released side by side. Pick the one that fits how you want to
start:

| Image | Release | What you get |
|-------|---------|--------------|
| **rpi5** (desktop) | `v0.1` (2-part split) | Pre-baked **Hyprland + Noctalia v5** desktop, user `ryuzaki`, wifi auto-connect. Flash both parts and boot — least hassle. |
| **rpi5-minimal** (vanilla) | `v0.2` (single file) | Lightweight base + `wifitui` + ssh. You log in at the console, join wifi, clone this repo, run `./setup.sh`, and rebuild with **your own** username/hostname/wifi. |

## What's here

```
flake.nix              Flake: nvmd installer + Noctalia v5, rpi5 + rpi5-minimal configs
configuration.nix      Desktop host config (reads local.nix + secrets.nix)
modules/desktop.nix    Hyprland + Noctalia + greetd autologin
modules/minimal.nix    Vanilla bootstrap config (wifitui + ssh + flakes)
modules/noctalia.toml  Seed config for the Noctalia shell (→ ~/.config/noctalia/config.toml)
modules/hyprland.conf  Seed config for Hyprland (→ ~/.config/hypr/hyprland.conf)
setup.sh               First-run wizard: prompts → local.nix/secrets.nix → rebuild → first-run.sh
scripts/first-run.sh   First-boot repair: fixes user home ownership, removes orphaned homes
build-image.sh         Build the image; optionally flash + grow an SD card
local.nix.example      Template for per-device personal config (copy to local.nix)
secrets.nix.example    Template for passwords (copy to secrets.nix)
FIRST_BOOT.md          First-boot guide for a freshly flashed card
```

`local.nix` and `secrets.nix` are **gitignored** — run `./setup.sh` to generate
them, or copy the `.example` files. They are marked intent-to-add in git so
Nix can read them during evaluation, without ever being committed.

## Build the images

On any machine with Nix flakes:

```sh
./build-image.sh                     # builds the rpi5 desktop image into ./images/
./build-image.sh -c rpi5-minimal     # builds the vanilla bootstrap image
./build-image.sh --list-configs
```

### Flash + grow an SD card

```sh
./build-image.sh --flash /dev/sda    # dd image, growpart, resize2fs
```

or manually:

```sh
zstdcat images/nixos-image-rpi5-kernel-*.img.zst | sudo dd of=/dev/sdX bs=4M status=progress conv=fsync
sudo growpart /dev/sdX 2 && sudo resize2fs /dev/sdX2
```

The `v0.1` release parts are reassembled first:

```sh
cat NIXOS_IMG_aa NIXOS_IMG_ab > nixos-image-rpi5-kernel.img.zst
```

## Which image to use?

### Desktop (`rpi5`, less hassle)

- Flash the two `v0.1` parts, boot, done — Noctalia + Hyprland start
  automatically with the `ryuzaki` user and the configured wifi.

### Minimal (`rpi5-minimal`, self-configured)

- Flash the single `v0.2` file and boot to a NixOS console.
- Log in with the default user (user `bootstrap`, password `changeme`, hostname
  `nixos-rpi5`), then:

```sh
# 1. join your wifi
sudo wifitui

# 2. clone this repo
git clone https://github.com/Ryuzaki5100/rpi-nixos
cd rpi-nixos

# 3. set your username, password, hostname and wifi
./setup.sh
```

`setup.sh` writes `local.nix` + `secrets.nix`, then runs
`nixos-rebuild switch --flake .#<hostname>` (the desktop config is exported
under the hostname you choose, per `flake.nix`), booting you into the full
desktop with **your** account. It then runs `scripts/first-run.sh` to fix the
fresh user's home permissions and clean up orphaned home dirs. Run that script

## Reproduce on another Pi

1. Give it a hostname/user/ssh key: either run `./setup.sh` (interactive) or
   edit `local.nix` + `secrets.nix` (and refresh `nixos-configuration` imports).
2. `./build-image.sh --flash /dev/sdX` (or flash the minimal image + rebuild).
3. Keep it updated on-device with
   `sudo nixos-rebuild switch --flake /etc/nixos#rpi5` (the flake is baked into
   `/etc/nixos` at activation). Plain `sudo nixos-rebuild switch` also works,
   since the desktop config is exported under the machine's hostname.

The build trusts the [`nixos-raspberrypi` cachix](https://nixos-raspberrypi.cachix.org)
for prebuilt kernel/firmware; Noctalia/Hyprland come from `cache.nixos.org`
via the pinned unstable nixpkgs.

## Layout gotchas

- `modules/desktop.nix` uses an **unstable** nixpkgs for the Noctalia package
  (binary-cached); the rest of the system builds from `nixos-26.05`.
- `local.nix` / `secrets.nix` are gitignored; generated by `./setup.sh`.
  Nix sees them because `setup.sh` runs `git add -N -f` + `--skip-worktree`,
  so they cannot be accidentally committed.
- Editing `configuration.nix` (or the `modules/`) takes effect on the next
  `nixos-rebuild switch`; the activation script syncs the repo to `/etc/nixos`.
